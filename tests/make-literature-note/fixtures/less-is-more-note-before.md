# Less is more, more or less

AI makes human understanding, judgment, and taste more important as production gets
cheaper, because the cost of deciding what should exist doesn't fall along with it.

## Source Points

### Claim 1: AI makes human understanding, judgment, and taste more important
Question: Does cheaper AI production reduce the value of human judgment?
Evidence: The source argues the opposite is true as production cost collapses.
Warrant: What's scarce shifts to whatever AI doesn't do — deciding what's worth keeping.
Conclusion: AI makes human understanding, judgment, and taste more important, not less.

### Claim 2: The value of AI tools depends on how deliberately a person uses them
Question: Does the source treat agent use itself as automatically valuable?
Evidence: The source frames agent use as something to be deliberate about, not avoided.
Warrant: Unexamined use of a powerful tool doesn't automatically produce good outcomes.
Conclusion: The value AI tools add depends on the deliberateness of how they're used.

### Claim 3: Simpler features reduce the cognitive load needed to use them correctly
Question: What does cutting scope on a feature actually buy a user?
Evidence: The source says a feature doing less is easier to reason about.
Warrant: Less surface area means less a person has to hold in their head at once.
Conclusion: Simplicity in a feature measurably reduces the cognitive load of using it.

### Claim 4: Judgment about what to cut is the real value added in code review
Question: What does a person add when reviewing AI-generated code?
Evidence: The source says the value is knowing which lines earn their place.
Warrant: An agent can produce working code; deciding what's worth keeping is separate.
Conclusion: Human judgment about what to keep or cut is the real value added in code.

### Claim 5: Agents can produce multiple working variations of the same task
Question: Does the source treat agent output as scarce or plentiful?
Evidence: The source describes a model happily generating ten variations, all fine.
Warrant: Cheap generation means quantity of output stops being the bottleneck.
Conclusion: Agents can readily produce several working variations of the same task.

### Claim 6: Judgment about what to keep or cut applies to reading agent output generally
Question: What is the actual skill in working with agent-produced transcripts or drafts?
Evidence: The source says the skill isn't writing it, it's reading it critically.
Warrant: If production is cheap, the bottleneck moves to selection and curation.
Conclusion: The same keep-or-cut judgment applies to reading agent output broadly.

### Claim 7: Standards and tools encode someone's prior judgment
Question: What is a style guide or linter config actually doing?
Evidence: The source calls these "somebody's prior decision about what to keep and cut."
Warrant: A rule applied automatically still reflects a judgment made once, earlier.
Conclusion: Standards and tools encode a person's judgment, applied automatically.

### Claim 8: Give agents narrow, explicit constraints before asking for output
Question: What's the first item in the source's own agent-habits list?
Evidence: The list's first bullet: give a narrow, explicit constraint before asking.
Warrant: Vague asks produce vague, sprawling output per the source.
Conclusion: Narrow, explicit constraints should precede any agent request.

### Claim 9: Treat agent output as plausible but unverified until checked
Question: What's the second item in the source's own agent-habits list?
Evidence: The list's second bullet: read output critically, assume wrong until checked.
Warrant: Plausible-sounding output isn't the same as correct output.
Conclusion: Agent output should be treated as unverified until checked, not trusted.

### Claim 10: Prefer asking an agent to cut rather than add when output feels bloated
Question: What's the third item in the source's own agent-habits list?
Evidence: The list's third bullet: prefer cutting over adding when output feels bloated.
Warrant: Bloat is usually solved by removal, not further generation.
Conclusion: A bloated agent output should be trimmed, not padded further.

### Claim 11: A standing style file keeps agent judgment consistent across sessions
Question: What's the fourth item in the source's own agent-habits list?
Evidence: The list's fourth bullet: keep a standing config file the agent can reference.
Warrant: Judgment applied once, then reused, is more consistent than re-deciding each time.
Conclusion: A standing style or config file keeps applied judgment consistent over time.

### Claim 12: Simple interfaces are easier to build on top of, mirroring simple features
Question: Does the cognitive-load benefit of simplicity apply beyond individual features?
Evidence: The source says the same reduction in cognitive load applies to a simple
interface or API, not just a single feature.
Warrant: The mechanism reducing load for a user is the same one reducing it for a builder.
Conclusion: Simplicity's cognitive-load benefit extends to interfaces and APIs generally.

### Claim 13: Judgment about what to keep or cut defines what makes a product great
Question: What separates a merely functional product from a great one, per the source?
Evidence: The source ties greatness to deciding, correctly, what a product should refuse to do.
Warrant: More features isn't the same as better judgment about which ones matter.
Conclusion: The same keep-or-cut judgment is what makes a product great, not feature count.

### Claim 14: Standards do the judging automatically once they exist
Question: Does a standard require re-litigating its judgment every time it's applied?
Evidence: The source says a standard "does the judging for you, every time, without asking."
Warrant: A rule fixed once removes the need to re-decide the same question repeatedly.
Conclusion: Once a standard exists, it applies its encoded judgment automatically.
